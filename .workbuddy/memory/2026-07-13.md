# 2026-07-13

## 分析：文章页点顶部导航返回主页触发整页刷新

- 根因：`src/components/widget/SideBar.astro` 的 `updateSidebar()`（绑定在 `page:view` 钩子上）在「离开文章页（wasPostPage=true）进入非文章页（nowIsPost=false）」时调用了 `window.location.reload()`，导致 Swup 过渡动画完成后立刻整页重载。
- 整个 src 中只有这一处 `location.reload()`（已 grep 确认）。
- 为什么只在 post→主页 出现：post→post 走 `nowIsPost=true` 分支不刷新；home→post 时 `wasPostPage=false` 不刷新；只有 post→任意非文章页 才命中 `else` 中的 reload。
- 为什么这个 reload 是多余的：SideBar 位于 `<main id="swup-container">` 内部（MainGridLayout.astro），是 Swup 的容器之一，每次导航 Swup 已整段替换 main（含正确侧边栏）。`@swup/astro` 自带 scripts 插件，会自动重跑脚本并重新 hydrate `client:only` 的 Svelte 岛屿（RouteSwitch/Categories/UmamiStats），无需硬刷新。
- 附带：`updateSidebar` 的 TOC 重建分支（post→post）同样冗余，因为 SideBarTOC 是服务端按文章正确渲染后由 Swup 替换的。
- 修复：已删除 SideBar.astro 中整个 `<script>` 块（含 `wasPostPage`/`updateSidebar`/`isPostPath`/`buildTocCardHtml`/`extractHeadings` 及 `page:view` 钩子注册）。该脚本只服务于这段冗余 hack，服务端 `isPostsRoute` 渲染逻辑不受影响。
- 用户要求「删除跳过验证环节」，故未跑 `pnpm check`/`pnpm build`。后续如需可补验：post→home 不再刷新、返回后侧栏 client:only 组件可交互、post→post 的 TOC 正常。

## 修正：为何删除 SideBar 脚本后目录（TOC）消失
- 重新检查 `MainGridLayout.astro` 后发现：`#sidebar` / `#sidebar-sticky` 并不在 Swup 的容器内。Swup 当前容器只有 `main` 和 `#toc`，因此**客户端导航时侧边栏不会被替换**。这就是为什么原来那段 `updateSidebar` 脚本并非冗余：它通过监听 `page:view` 手动把侧栏从 widgets 重建成 TOC（文章页）或触发 reload（离开文章页）。
- 我之前删除该脚本后，虽然 `SideBar` 服务端仍会按当前页面渲染 TOC，但 Swup 只换 `main`/`#toc` 不换侧栏。比如从主页进入文章，侧栏仍然保留主页的 widgets（RouteSwitch/Categories/UmamiStats），所以看不到目录。
- 正确做法：让 Swup 自动处理侧栏。已将 `#sidebar-sticky` 加入 `astro.config.mjs` 的 Swup `containers`：
  ```js
  containers: ["main", "#toc", "#sidebar-sticky"],
  ```
  这样每次导航 Swup 都会把 sticky 侧栏内容换成目标页服务端渲染好的版本（文章页为 TOC，非文章页为 widgets），`updateSidebar` 脚本可以彻底删除，也不再需要 reload。
- 保留 `Profile` 在 sticky 之外（`#sidebar` 内），不会被重复替换，减少闪烁。
- 之前 `transition.css` 的 `opacity:0` 修复保留作为安全网：侧栏被 Swup 替换后，内部的 `client:only` Svelte 组件和 `.onload-animation` 元素若因动画不重放而卡隐身，仍可保持可见。
- 待验证：文章页进入后目录显示正常；离开文章页到主页/归档/关于时侧栏自动切换回 widgets；文章↔文章切换时目录更新；没有整页刷新。
