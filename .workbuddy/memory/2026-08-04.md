## memos 动态页 /api/memos 404 根因与修复（已纠正理解）

- **项目实际是双部署（两个分站）**：
  - **flygeon.top = 独立 Cloudflare Worker 部署**（用户原话：既在 GitHub Pages 也在 Cloudflare Workers 上部署；flygeon.top 本身是 CF Worker，GitHub Pages 是另一个分站）。
  - GitHub Pages 通过 `.github/workflows/deploy.yml`（`withastro/action@v5` + `actions/deploy-pages@v4`）部署，是纯静态分站。
- **真正根因**：`/api/memos` 原本写在 `functions/api/memos.ts`，是 **Cloudflare Pages Functions 格式（`onRequest`）**，但 flygeon.top 跑的是**独立 Cloudflare Worker**，根本不会加载 `functions/` 目录里的 Pages Function。所以请求落到 Worker 上无对应 handler → 404。（之前以为是 GitHub Pages 跑不了 functions，是误判；trailing-slash 308 只是表象，不是根因。）
- **memos API 实测**：`GET https://memos.flygeon.top/api/v1/memos?filter=visibility=='PUBLIC'` 无 token 返回 `401 authentication required`；带 `Origin: https://flygeon.top` 时返回 `access-control-allow-origin: https://flygeon.top`（CORS 已放行）。结论：token 必须服务端持有，浏览器不能直连。
- **正确修复（已提交推送 3213928）**：新增 `worker/memos-proxy.js`（**标准 Worker `fetch` 入口**，非 Pages Functions）+ `worker/wrangler.toml`（路由 `flygeon.top/api/memos*`）。Worker 在边缘拦截 /api/memos* 并代理 memos，token 存 `MEMOS_TOKEN` 环境变量。前端无需改动。
- **已回滚误操作**：把之前误把 `functions/api/memos.ts` 重构成 `index.ts` 的改动还原了（`git checkout 149099c -- functions/api/memos.ts` + 删 index.ts）。`functions/api/memos.ts` 仍是原样（Pages Functions 格式，对当前 Worker 部署是死代码，但保留原状）。
- **待用户操作（需要其 Cloudflare 凭证）**：在 `worker/` 目录 `wrangler login` → `wrangler secret put MEMOS_TOKEN` → `wrangler deploy`。注意 flygeon.top 已有主 Worker 服务整站，本 Worker 路由 `flygeon.top/api/memos*` 更具体、应优先匹配；若主 Worker 已有 /api 处理逻辑则需把这段逻辑并进去。
