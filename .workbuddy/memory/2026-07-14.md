## 修复目录高亮条仍不出现（彻底重写——根因：视觉输出完全无效）
- 用户反馈连续两次修复后，高亮条仍然没有出现。决定不再修修补补，而是对整个渲染链路做**端到端的根因分析**。

### 确认的两大视觉失效原因

**原因 A：`.visible` CSS 类没有任何可见效果**
- 从构建产物 `dist/_astro/_page_.B96f6lQU.css` 提取确认：`.visible { visibility: visible }`
- 这是 Tailwind 内置工具类，而所有 HTML 元素默认就是 `visibility: visible`
- 全项目搜索确认不存在任何让 `.visible` 改变颜色/背景/字重的 CSS 规则
- 因此脚本中 `classList.add("visible")` / `classList.remove("visible")` 对目录条目外观**零影响**

**原因 B：active-indicator 被卡片背景完全遮挡**
- 指示条 div 带有 `-z-10` 类 = `z-index: -10`（渲染在父元素背后）
- 外层包裹有 `card-base` 类 = `background-color: var(--card-bg)` = `white`（不透明白色）
- 右侧原版 TOC 无 card-base 包裹、容器透明，所以 `-z-10` 的指示条能透出；但侧栏版本被实底白卡挡住
- 即使 JS 正确将指示条 opacity 设为 1、位置正确，也永远看不见

### 结论
JS IntersectionObserver 逻辑本身**大概率在正常运行**（能触发回调、更新 active 数组、定位 indicator），但所有输出都因为以上两条视觉原因无法呈现到屏幕上。

### 修复方案（完全重写 SideBarTOC.astro 脚本）
- **废弃**原 IntersectionObserver + fallback 双轨系统（过于复杂且依赖 remark-sectionize 生成的 section DOM 结构）
- **改用**简单的 scroll 事件 + rAF 节流方案：
  - `init()` 扫描 `[data-sidebar-toc-entry]` 链接 → 通过 hash 取 heading DOM 元素（直接 `document.getElementById`，不依赖 section）
  - `onScroll()` 用 rAF 防重入，`update()` 以视口 25% 高度为触发线、倒序遍历 headings 取最后一个越过触发线的为 activeIndex
  - **高亮方式**：直接对 active 条目的 `<a>` add/remove Tailwind 类 `bg-[var(--toc-btn-hover)] text-neutral-900 dark:text-neutral-100`——立即生效、不依赖任何外部 CSS 规则
  - **指示条**：`z-index: 1`（正数，在内容之上）、`pointer-events-none`（不影响交互）、`duration-300` 过渡
  - activeIndex 不变时 early return，避免无意义的 DOM 操作
- **模板改动**：
  - `<a>` 标签加 `data-sidebar-toc-entry` 属性（替代之前的 `a[href^='#']` 选择器）
  - 移除 `<a>` 上的 hover/active 背景 class（由 JS 动态添加，避免与高亮冲突）
  - indicator 改用 `data-toc-indicator` 属性选择器；去掉 `-z-10` 和 `group-hover` 相关类；内联 `style="opacity:0; z-index:1"`
- 验证：tsc --noEmit 通过。

## 关键根因：自定义元素升级链路不可靠 + TailWind 未生成动态类
- 用户连续反馈高亮不出现，且敏锐指出"是不是高亮层级错、被放到卡片底部遮住了"。
- **确认**：指示条 `#sidebar-active-indicator` 是 `position:absolute`，无 `top` 时停在文档流默认位置（所有 `<a>` 之后=卡片底部），同时 `opacity:0`。只要 `update()` 不执行，它就永久卡在卡片底部+不可见——与用户描述完全吻合。这说明 **JS 的 `update()` 压根没跑起来**。
- **真正的根因（前两版都踩）**：用**自定义元素 `sidebar-table-of-contents` + `connectedCallback`**。在 Astro + Swup 环境里，自定义元素的"升级（upgrade）链条极其脆弱——脚本须成功执行→`customElements.define`→元素升级→`connectedCallback`→`init()`。只要任一环（脚本解析/define/upgrade 时机）失败，整条断，`update()` 永不执行，指示条卡在卡片底部。
- **第二个叠加 bug**：前两版用 `classList.add("bg-[var(--toc-btn-hover)]")` 动态加 TailWind 任意值类。该字符串只出现在 JS 里、**源码 HTML 中没有**，TailWind JIT 很可能**没扫描到、根本没生成这个类**，导致即便 `update()` 跑了，高亮类也不生效。
- **修复（完全重写，三处根因一并消除）**：
  1. **抛弃自定义元素**：改用普通 `<script>` + 标准 DOM 查询，`bootSidebarToc()` 在 `DOMContentLoaded`（或已 ready 时立即）执行，并挂 `window.swup.hooks.on('page:view', ...)` 在每次 Swup 导航后重新 init。用 `WeakSet` 防同一元素重复初始化。不再有"升级时机"这一环。
  2. **高亮改用普通 CSS**（不依赖 TailWind 扫描）：组件内加 `<style is:global>`，用唯一 ID `#sidebar-toc-inner-wrapper` 作用域定义 `.toc-active` 类（背景 `var(--toc-btn-hover)` + 文字 `rgb(23 23 23)` / 暗色 `html.dark` 下 `rgb(245 245 245)`）和 `#sidebar-active-indicator { background-color: var(--toc-btn-hover); }`。JS 只 `classList.toggle("toc-active", i===idx)`，100% 确定生效。
  3. **指示器补背景色**：之前漏给指示器加背景，现由 `<style is:global>` 的 `#sidebar-active-indicator{background-color:var(--toc-btn-hover)}` 提供；内联 `z-index:2` 确保在其内容之上、卡片白底之下（卡片外层无 z-index、不创建层叠上下文，故 z-index:2 在根层叠上下文里高于卡片背景）。
- 暗色模式确认：项目用 `<html>` 上的 `dark` class 切换（`tailwind.config.cjs` 中 `darkMode:"class"`），故 `html.dark` 选择器正确。
- 逻辑：scroll 事件 + rAF 节流；以视口 25% 高度为触发线，倒序遍历 headings 取最后一个越过触发线的为本节 active；切换时同时给 `<a>` 加 `.toc-active` 背景高亮、并定位滑动指示器。
- 验证：纯 JS 已用 `node --check` 通过（无 TS 注解，零转译风险）。

## 修复 Cloudflare 构建失败：src 内 .bak 备份被 astro build 解析（用户贴 CI 报错）
- 现象：本地 dev 正常，但 Cloudflare Workers `astro build` 报 `[vite:build-import-analysis] ... SideBarTOC.astro.bak.20260714 (34:61): Failed to parse source ... invalid JS syntax`。
- 根因：之前回滚/恢复时留在 `src/components/widget/` 里的两个备份 `SideBarTOC.astro.bak.20260714` 与 `.bak.block.20260714` **被 git 跟踪并提交**。dev 不扫这些文件，但 `astro build` 的 Vite import-analysis 会把 `src` 下所有文件当源码解析 → `.astro` 里的 `class:list` 等语法在 `.20260714` 扩展名下无法解析而报错。
- 修法：
  1. 把两个 .bak 从 `src/` 移到项目根的 `.toc-backups/`（构建不扫 src 外目录，备份仍保留可还原）。
  2. `.gitignore` 追加 `.toc-backups/`、`*.bak`、`*.bak.*`，防止再次误提交。
- 关键提醒：备份已被提交，需 `git add -A && git commit` 提交删除（当前 git status 显示两文件为 `D`）后 CI 才会生效。教训：**永远不要把备份文件放在 `src/` 下**，即使扩展名非常规也会被 Vite import-analysis 解析。
