### Turnstile「通过验证后提交提示人机验证失败」（15:18 新现象）
- 现象：widget 能出现、能完成验证，但点提交评论返回 `{"ok":false,"message":"人机验证失败"}`（createComment.ts:31）。
- 前端已确认无误：`comments.js:926` 提交时 `turnstileToken: root.__yuuCommentsTurnstileToken` 已正确带入；`setupTurnstile` 的 callback 填 token、expired/error-callback 清空。
- 后端逻辑：`verifyTurnstileToken`(turnstile.ts:5) 用 `env.TURNSTILE_SECRET_KEY` + token 调 `siteverify`；secret 为空返回 `allowDevBypass`（量产后 hostname≠localhost 故为 false）；token 空或校验不成功返回 false。
- 已核实：`pnpm wrangler secret list --config worker/wrangler.toml` 显示 `TURNSTILE_SECRET_KEY` **已设置**（与 ADMIN_TOKEN 同在）→ 排除「未设密钥」。
- 结论：根因是**前端 site key 与后端 secret key 不属于同一个 Turnstile widget**（错配）。widget 能渲染只说明前端 site key 有效，但后端 secret 来自另一个 widget → token 校验失败。
- 修复：确保 Pages `PUBLIC_TURNSTILE_SITE_KEY` 与 `wrangler secret put TURNSTILE_SECRET_KEY` 来自**同一个** widget；最稳是新建一个 widget，两端统一用这一个。`secret put` 会自动重部署 Worker，无需单独 `pnpm deploy`，也无需重部署博客（除非同时改了前端 site key）。
- 已加诊断：修改 turnstile.ts 与 createComment.ts，使验证失败时返回 Cloudflare 真实 `error-codes`，并去掉 `remoteip`、对 secret 做 trim（防御复制带空格）。`pnpm deploy` 已重新部署（版本 8f891037-0acc-47ad-b476-63500b0c7477）。`codes` 字段为临时诊断，修好后需移除、恢复干净提示。
- **站长实测反馈 `codes:["invalid-input-secret"]`** → 定论：Worker 的 `TURNSTILE_SECRET_KEY` 与前端 site key 不属于同一 widget（或该 secret 已轮换/复制错/带脏字符）。widget 能渲染只证明前端 site key 有效，secret 仍是错的。
- 修复（站长执行）：新建一个 Turnstile widget，Site Key→Pages `PUBLIC_TURNSTILE_SITE_KEY`+重部署博客；Secret Key→`pnpm wrangler secret put TURNSTILE_SECRET_KEY --config worker/wrangler.toml`（自动重部署 Worker）。或用原 widget 时务必对着 Pages 里的 site key 值找到对应 widget 再复制其 Secret（若轮换过须用新 secret）。
