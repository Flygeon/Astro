### 已识别的阻塞点与风险
1. **无 Cloudflare 凭据**：本机无 wrangler、无 `~/.wrangler`、无 `CLOUDFLARE_API_TOKEN` → 无法代为部署
2. **Swup 冲突（必改）**：`comments.js` 的 `init()` 仅在 DOMContentLoaded 触发一次（`{once:true}`），
   无 SPA 感知；本站 swup `containers:["main","#sidebar-sticky"]` + `updateHead:false`
   → 软导航进文章页评论区不会加载，必须自写组件监听 swup 事件重挂载
3. **老评论无法自动迁移**：YuuComments 的 import/export 工具在 roadmap 里标记为未完成
4. **部署管线三方冲突**：CLAUDE.md 说 Cloudflare Pages / 存在 vercel.json / deploy.yml 部署 GitHub Pages
   且 deploy.yml 只在 `main` 触发，本地当前分支是 `master`
5. 上游 `frontend/astro/*.astro` 用了裸 `<script src="/comments/comments.js" defer>`，
   Astro 引用 public/ 下脚本通常需要 `is:inline`，需构建验证
6. YuuComments 自述 "early development"，v1.0 前 API 与 DB schema 不保证稳定

### 站长部署报错修复（wrangler: No configuration file found）
- 报错根因：配置在 `worker/wrangler.toml`（子目录），但命令在仓库根目录跑、没带 `--config worker/wrangler.toml`，wrangler 默认找根目录 wrangler.jsonc/toml 找不到。
- 正确做法：所有 wrangler 命令带 `--config worker/wrangler.toml`，或直接 `cd worker` 后跑；`wrangler` 未全局安装时用 `pnpm wrangler ...`（或仓库已配好的脚本 `pnpm db:migrate:remote` / `pnpm deploy`）。
- 已修正 docs/yuucomments-deploy.md：1.3 迁移命令加 `--config worker/wrangler.toml`（并提示用 `pnpm db:migrate:remote`）、1.2 加「已填 database_id 可跳过」+ `wrangler d1 list` 校验提示、第 4 节 execute 加 `--config`。migrate-old-comments.sql 顶部注释同步修正。

### 关键 BUG 修复：wrangler.toml 的 D1 binding 名与代码不一致（会导致部署成功但运行时 500）
